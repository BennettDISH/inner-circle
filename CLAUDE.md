# inner-circle

Friends-and-family sharing app: people join circles by code and post what they have or need; others send requests on a listing. Express 4 serves the built React 19 app and a JSON API. Live on Railway at https://inner-circle-production-a7f8.up.railway.app. Default branch is `master`.

## Commands
```bash
npm run server       # node --watch server.js (API on PORT, default 3000)
npm run dev          # Vite dev server, proxies /api to localhost:3000
npm run build        # vite build -> dist/
npm start            # node server.js (serves dist/ + /api)
npm test             # node --test test/*.test.js
```
`npm test` spawns the real `server.js` against PGlite served over the Postgres wire protocol, with a stand-in Waypoint for register/login and the code exchange (it can also send a guest, to prove the app refuses one) (`test/helpers.js`, which pins every env var the server reads). The helper drops the extra ReadyForQuery PGlite sends after an extended-protocol error; without that, the ROLLBACK in circle create gets out of step with `pg` and the server dies. `test/api.test.js` covers the routes and the schema's indexes, `test/admin.test.js` the admin lists, `test/guestSweep.test.js` the sweep (straight against PGlite), `test/limits.test.js` the join-code and Waypoint sign-in limits, `test/sso.test.js` the refusal of guests, `test/joinCode.test.js` how join codes are drawn and the retry on a clash (straight against PGlite), `test/csp.test.js` the Content-Security-Policy against what `index.html` and the SCSS actually load (it serves the pages from a throwaway `dist/` through `DIST_DIR`, which only the tests set, so no build has to run first), and `test/db.test.js` checks the pool on its own in a child process. Each `app.user()` registers a new account, and every `app.request()` with no headers of its own is sent, from its own client address (`X-Forwarded-For`, as Railway's edge sends it), so the per-address limits don't run out; pass an address, or headers as the fourth argument of `as`, to pick one. No lint script. A local run needs Postgres in `DATABASE_URL` and the Waypoint vars, since every sign-in goes through the auth service.

## Key files
- `server.js`: `trust proxy` 1 (Railway's one hop, so `req.ip` is the real client; never `true`), helmet with a Content-Security-Policy (helmet's defaults plus the bug-tracker widget's origin in script-src and connect-src, Google Fonts, data:/blob: images; a new outside script, stylesheet, font or API needs adding there), open CORS, morgan, JSON body; routers under `/api/auth`, `/api/circles`, `/api/listings`, `/api/requests`, `/api/admin`; any other `/api` path is a JSON 404; `/health` (`routes/health.js`); SPA fallback. Boot runs `initDb()` first and exits if it fails, then schedules the guest sweep.
- `routes/health.js`: `GET /health` runs one `SELECT 1` with a 3 second limit: 200 `{ status: 'ok', db: 'ok' }`, or 503 `{ status: 'unavailable', db: 'not answering' }` with no database text; `no-store`. `healthHandler({ query, timeoutMs })` takes a stand-in query for tests (`test/health.test.js`). The Railway healthcheck path is a setting on the service, not in the repo.
- `config/db.js`: the pool (its `error` listener logs a dropped idle connection instead of crashing), `toId()` (routes check every id with it: an int4 or null, which they answer with 400), and the whole schema, applied on every boot. No migrations; keep changes idempotent (`IF NOT EXISTS`, `DROP COLUMN IF EXISTS`). Every foreign key column leads an index; a test fails if a new key doesn't.
- `services/guestSweep.js`: a minute after boot and then daily, removes Waypoint guests (`guest-adj-noun-NNNN` usernames) not signed in for `GUEST_RETENTION_DAYS` (30), with the circles only such guests had a part in. `GUEST_CLEANUP_ENABLED=false` turns it off. The header comment explains what it may take.
- `config/sso.js`: `centralRegister`, `centralLogin`, `exchangeCode`. `SSO_ENABLED` needs all three SSO vars.
- `middleware/rateLimit.js`: in-memory fixed-window counters (`createLimiter({ max, windowMs })` with `blocked(key)` and `hit(key)`), cleared by a redeploy. Used for 10 wrong join codes per 15 minutes per address and per account (`routes/circles.js`; right codes aren't counted) and 10 Waypoint sign-in tries per 15 minutes per address (`routes/auth.js`; the password login and the SSO return share those ten, every try counts, because Waypoint counts `/api/auth/proxy/login` and `/oauth/token` in one bucket of 30 per 15 minutes for this whole server's address; registering isn't limited here), then 429. Each limiter is its own count.
- `middleware/auth.js`: `authenticate` verifies the Bearer JWT (`{ central_user_id, username }`) and loads the profile; `req.user.is_admin` comes from `ADMIN_CENTRAL_USER_IDS`.
- `routes/auth.js`: config, SSO start, register/login (proxied to Waypoint), sso-callback, profile; all three sign-ins answer 403 for a Waypoint guest (`is_guest`) before any profile or token is made. `findOrCreateProfile` mirrors the Waypoint account into `profiles` with one upsert that stamps `updated_at` (the sweep's "last seen").
- `services/circles.js`: `nameError`/`textError` (a circle name or listing title is text of at most 255 characters, the VARCHAR(255) columns, counted as Postgres counts them; NUL is refused everywhere; the routes answer a plain 400), `generateJoinCode` and `insertCircle`. The inputs for the two carry `maxLength={255}`.
- `routes/circles.js`: list mine, create (creator becomes circle `admin`; any failure past the checks rolls back and is a 500, never Postgres's own message), join by code, view (members only), leave.
- `routes/listings.js`: list by circle (members only), create, update/delete (owner only), mine. Update leaves out (or null) what it doesn't change; a blank title or a non-boolean `active` is a 400. Lists carry each listing's `photos: [{ id }]`. Photos (off until R2 is set up): `POST /:id/photos` (owner only; raw image body, jpeg/png/webp by magic bytes, 2 MB each, 4 a listing, 50 MB a day per account in memory, 503 when R2 is off), `GET /:id/photos/:photoId` (circle members, or the owner; streams the object with `private, max-age=31536000, immutable`), `DELETE /:id/photos/:photoId` (owner). An `<img>` cannot send the Bearer token, so the page fetches photos with it and shows a blob URL (`src/components/AuthImage.jsx`). Deleting a listing deletes its objects.
- `config/r2.js`, `services/photos.js`: the R2 (S3 API) client, enabled only when `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` and `R2_BUCKET` are all set (`/api/auth/config` says `photos`); the private bucket has no public URL, so there is no `R2_PUBLIC_URL`. Objects are `circles/<circleId>/<24 hex>.<ext>` with `Cache-Control: private, max-age=31536000, immutable`; `listing_photos` holds the keys. Object deletes are best effort and logged (listing delete, photo delete, and the guest sweep for the circles it takes). The tests (`test/photos.test.js`, `test/photoSweep.test.js`) put a fake S3 client in place of R2 (`test/fakeR2.js` is preloaded into the spawned server).
- `routes/requests.js`: create on an active listing in a circle you're in (409 for an inactive listing, or when you already have a pending request on it; the listing row is locked in the create transaction so two at once can't both pass), list incoming/outgoing, update status. Only the listing owner sets `accepted`, `declined` or `completed`; the person who asked can only set `cancelled`, and only while the request is `pending` or `accepted`; nobody sets `pending`; the owner can't change a cancelled request (409s). The UI cancels from the Outgoing tab.
- `routes/admin.js`: site admin lists under `/api/admin` (users, circles, members, listings, requests), GET only, 403 unless `req.user.is_admin`. Each answers `{ items, total, page, page_size }` (50 a page) and takes `q` (ILIKE anywhere, `%` and `_` literal), `page` and id filters. Join codes never come out. `src/pages/Admin.jsx` is the page; the nav shows it to admins.
- `src/services/api.js`: fetch wrapper that adds the token from localStorage.
- `src/contexts/AuthContext.jsx`, `src/components/ProtectedRoute.jsx`: session and route guard.

## Conventions and gotchas
- Guests: no, because personal sharing (people trade with and ask real friends and family, and a guest can never sign back in to read an answer). Waypoint's sign-in page offers "Continue as guest" whatever an app wants, so `routes/auth.js` refuses `is_guest` at the SSO callback (and register/login) with a 403, and `src/pages/AuthCallback.jsx` passes the reason to the sign-in page. There is no guest route or button. `services/guestSweep.js` stays only to clear guest accounts that signed in before 2026-10-23; they are not deleted by hand.
- Users are keyed by `central_user_id` everywhere (all foreign keys point at `profiles.central_user_id`), not by a local id.
- There are no local passwords: register and login are proxied to Waypoint; the app only issues its own JWT afterwards.
- Membership is the access rule: check `circle_members` before showing anything in a circle.
- Listing kinds are `have` and `need`; categories are validated against `VALID_CATEGORIES` in `routes/listings.js`.
- `is_admin` (from `ADMIN_CENTRAL_USER_IDS`; unset means nobody) only opens the look-only admin lists. It gives no member or owner powers inside circles.
- Join codes are 6 characters of 0-9 and A-Z drawn with `crypto.randomInt`; the wrong-code limit is what keeps them from being guessed. If a new code is already taken, `insertCircle` tries one more inside the create transaction (a savepoint, so the transaction survives), then gives up with a 500.
- The Railway build installs devDependencies on purpose: vite is a devDependency. Build and start commands are set on the Railway service itself; there is no `railway.toml`.
- Env vars are named in the README and explained in `.env.example`. Never commit `.env`.
